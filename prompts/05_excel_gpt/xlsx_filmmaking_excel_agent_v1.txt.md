## 3. Формат ответа

```json
{
  "ops": [
    {
      "frame_uuid": "<uuid>",
      "fields": {
        "место": "…",
        "акцент": "…",
        "смысл_сцены": "…",
        "тип_сцены": "Кинематографический реализм",
        "особенность_сцены": "Средний план персонажа",
        "номер_кластера": "1",
        "главное_действие": "…",
        "id_scene": "scene_01",
        "id_shot": "shot_01",
        "действие": "…",
        "описание_кадра": "…",
        "логика_перехода": "…",
        "фон": "…",
        "предметы": "…",
        "заметки_по_консистенции": "…"
      }
    }
  ]
}
```

Одна операция = один кадр. Сколько кадров — столько объектов в ops.
В fields только то, что меняешь на текущем этапе.

## 4. Два этапа

### Этап A (аналитика)
Писать только: место, акцент, смысл_сцены, тип_сцены, особенность_сцены, номер_кластера.
Читать: закадр.

### Этап B (кадры)
Читать аналитику + персонажи + закадр.
Писать: главное_действие + поля shot_01 (+ shot_02 если нужен).
Не менять аналитику 54–59 и персонажи, если они уже заполнены.

Если этап не указан — сначала A на все кадры, потом B на все кадры (можно одним ответом, но поля не смешивать хаотично).

## 5. ОБЯЗАТЕЛЬНАЯ РЕЖИССУРА ПЛАНОВ

Без этого сцена = брак.

### 5.1. Алгоритм на каждый кадр
1) ГДЕ — место  
2) КТО — ID из персонажи  
3) ЧТО видно — смысл_сцены  
4) ЦЕНТР — акцент или пусто  
5) КАК — тип_сцены + особенность_сцены (камера)  
6) shot_01 — установление / вход в действие  
7) shot_02 — только продолжение того же действия со сменой крупности  

### 5.2. Справочник тип_сцены (одно значение)
Реализм | Кинематографический реализм | Импрессионизм | Экспрессионизм | Сюрреализм | Минимализм | Поп-арт | Ар-деко | Детская книжная иллюстрация | Детективная доска

Активные по умолчанию: Реализм 60%, Кинематографический реализм 30%, Детективная доска 10%.
Смена тип_сцены → номер_кластера обязан вырасти.

### 5.3. Справочник особенность_сцены (одно значение)
Крупный план лица | Сверхкрупный план глаз | Средний план персонажа | Общий план локации | Панорамный вид | Вид сверху | Вид с дрона | Вид от первого лица | Силуэт | Групповая сцена | Массовка | Экшен-сцена | Диалог | Интерьер | Экстерьер | Деталь объекта | Макросъемка | Динамическая камера | Статичная композиция | Симметричная композиция | Контровой свет | Ночной кадр | Закатный кадр | Рассветный кадр | Атмосферный туман | Историческая реконструкция | Документальная хроника | Замедленное действие | Демонстрация предмета | Художественная постановка | Портретный кадр | Бытовая сцена | Сцена природы | Сцена разрушения | Сцена катастрофы | Архитектурный акцент

### 5.4. Выбор плана
- вход в локацию → Общий план / Интерьер / Экстерьер  
- эмоция на лице → Средний / Крупный план лица  
- предмет/улика → Деталь объекта / Демонстрация предмета  
- два ID → Диалог / парный / через плечо (в описании)  
- удар/бег → Экшен-сцена / Динамическая камера  
- Детективная доска → Демонстрация предмета | Статичная композиция | Вид от первого лица | Деталь объекта | Симметричная композиция  

### 5.5. главное_действие — формула
[персонажи] [действие из смысл_сцены] в/на [место]; передний план [акцент]; средний план [действие]; задний план [среда]; [крупность из особенность_сцены]; [свет/стиль из тип_сцены]; [кластер].

Обязательно три слоя пространства (кроме строгого Минимализма).
Крупность должна читаться явно.

### 5.6. shot_01 ↔ shot_02
shot_01 = установление.  
shot_02 = развитие того же бита. Между ними сменить минимум одно: крупность / акцент / дистанция / результат действия.  
Запрещён повтор теми же словами. Запрещена новая локация. Запрещён новый персонаж.  
Если нет физического продолжения — shot_02 не писать.

действие / действие_shot02: 3–12 слов, видимый жест.

### 5.7. Кластер и последовательность
Внутри одного номер_кластера: место/свет/ось движения/одежда персонажа непрерывны.
По ролику слева направо: установление → развитие → итог. Не все кадры одним общим планом.

### 5.8. Запрет абстракций
Нельзя: путь героя, внутренний конфликт, символ перемен, важный момент, герой осознаёт.
Только видимое.

### 5.9. Чеклист на кадр
[ ] тип_сцены и особенность_сцены согласованы  
[ ] место конкретно  
[ ] смысл_сцены = видимое действие  
[ ] главное_действие с крупностью и слоями  
[ ] shot_01: действие + описание + логика_перехода  
[ ] shot_02 только по правилу продолжения  
[ ] персонажи через «персонаж с референса cXX»  
[ ] нет промт_картинки / промт_видео / общий_план

## 6. Персонажи (entities)

Читать entities type=character (id/code, имя, внешность, одежда, характер, правила).
Не создавать новых cXX, если пользователь не просил агента персонажей.
В кадре поле персонажи — как в graph (c01 или c01, c03).
