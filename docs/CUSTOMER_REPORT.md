# Управляющий слой (AI-оркестратор): отчёт для заказчика

Обновлён 2026-10-06. Принцип плана соблюдён: оркестратор не переписывает код проекта. Он работает только с заранее описанными
нодами, профилями моделей и параметрами; серьёзные изменения и утверждение результатов остаются за человеком. Каждое утверждение
ниже указывает, чем оно подтверждено; чего не проверяли, помечено прямо. Технические детали и команды — `docs/STAGE_STATUS_REPORT.md`,
по нодам — `docs/NODE_COVERAGE.md`, по командной строке — `docs/ACTION_LAYER.md`, для команды — `docs/ORCHESTRATOR_QUICKSTART.md`.

## Что есть сейчас

1. **Наблюдение и аккуратное восстановление нод** (этапы 1-6 плана). Оркестратор ведёт журнал событий каждой ноды, классифицирует
   сбои, один раз повторяет упавшую текстовую ноду или докачивает уже оплаченное медиа, а решения принимает только из заранее
   разрешённого списка. Покрытие по 24 типам нод ниже.
2. **Командная строка (слой действий).** Оператор пишет фразу по-русски, видит план с риском и стоимостью и только потом выполняет;
   платное и стирающее выполняется после подтверждения человеком на сервере. Каталог на 2026-10-06: 83 действия (18 чтение, 31 локальная
   запись, 33 стирающие, из них 7 ещё и тратят деньги, 1 только платное без стирания), потолок плана 200 кредитов, журнал, аварийный стоп.
3. **Контроль изменений.** Предложение, разница, подтверждение человеком, версия, чтение обратно, откат. Меняются промпты и параметры
   нод `plan`, `script`, `split`, `excel_gpt` в заданных пределах; код и логика не меняются никогда (уровень T3 — только заметка разработчику).

## Покрытие по типам нод (24 типа: 23 рабочих и виртуальный `excel_gpt`)

Итог из данных кода (`GET /api/projects/{id}/observations/node-coverage`): под управлением 11 типов, под наблюдением 12, только человек 1;
автоматическое восстановление у 8 типов. «Под управлением» значит: принят исполнитель и независимая проверка результата.

## Командная строка: что проверено

- **Сквозной путь через HTTP** (`tests/test_e2e_action_layer_http.py`, 20 проверок, без сети): фраза → план (модель подменена) → подтверждение
  → запуск → результат → журнал, на реалистичном проекте из 30 кадров. Подтверждено фактами: чтение запускается без подтверждения; обмен шотов
  меняет данные в базе и возвращается повторной командой (отдельного «обратного плана» в каталоге нет, обратимы 5 действий); платное и стирающее
  без подтверждения не запускаются (403); подтверждение одноразовое (повтор того же плана и запуск нового плана по старому подтверждению отклонены);
  подмена шагов после подтверждения отклоняется (`plan_changed`); потолок кредитов не пускает план дороже потолка (`over_budget`), а снижение потолка после подтверждения останавливает шаг до старта; аварийный стоп отклоняет составление и запуск и останавливает идущую фоновую задачу;
  вложение → загрузка озвучки реально кладёт файл в проект; устаревший план (проект изменился) отклоняется (`stale_context`); план с шагом чужого проекта и вложение чужого проекта отклоняются; журнал нельзя править.
- **Реальный сервер и браузер** (Chrome, 2026-10-06, скриншоты `C:\video-pipeline\_ui_check\cmdline\30…42`): те же сценарии нажатием кнопок в Studio —
  чтение, обмен шотов, стирающее с диалогом подтверждения, платное не помещается в потолок (кнопка подтверждения заблокирована), аварийный стоп из панели,
  журнал. Платные и стирающие действия в этих прогонах **тестовые** (в памяти, денег не тратят).
- **Не проверялось:** ни одной живой платной генерации через командную строку (баланс Kie был отрицательным); настоящее поведение модели на
  стороне заказчика; нагрузка.

## Точность планировщика (живой прогон на настоящей модели)

| Этап | Результат | Набор |
|---|---|---|
| Первый замер | 57% | 260 фраз по-русски (чтение, правки, очередь, сцены, удаление, ноды, мастер-промты, контроль изменений, загрузки, уточнения, отказы) |
| После доработки каталога и правил | 89% | те же 260 |
| После доработки формулировок | **96%** | те же 260 |
| Новые фразы про медиа и вложения | **94%** | 16 новых фраз |
| Фразы-отказы (удали проект, запушь в гитхаб, измени код и подобные) | **100%** | 24 фразы-отказа |

Честные границы этих цифр:

- 96% измерено **на наших же фразах**, на которые систему доводили. На живых формулировках команды цифра будет ниже; для этого есть
  `scripts/add_eval_case.py` и порядок в `docs/ORCHESTRATOR_QUICKSTART.md` (раздел 7).
- Модель недетерминирована: одна и та же фраза в редких случаях (около 3%) даёт разные планы. Поэтому любой план сначала только показывается.
- Точность не означает безопасность: безопасность обеспечивает не модель, а сервер (строгая проверка параметров, показ только нужных действий, подтверждение человеком, потолок, журнал).
- Цена прогона нод и планов — верхняя оценка, не откалибрована по реальным счетам (калибровка есть только для gpt-5.6-sol).

## Какие ограничения остаются (сводка)

- Повторная платная отправка медиа по сбою оркестратором и командной строкой не допущена (повторы медиа не допущены, возобновление есть).
- Публикация только человеком.
- Outsee: нет идентификатора задачи, докачать нечего; неизвестный исход отправки блокирует повтор на окно времени, снять блокировку может человек после сверки кабинета.
- `project.resume` и `project.continue_pipeline` через командную строку подтвердить нельзя (стоимость следующего шага неизвестна).
- Цены не откалиброваны; потолок плана по умолчанию 200 кредитов (около $1).
- Живое восстановление `plan`, `script`, медиа-нод и живые платные прогоны командной строки не делались.
- Качество содержания результата (смысл, красота) не оценивается.
- Схема базы расходов трекера теперь меняется версионными миграциями, а не ручным дописыванием столбцов при каждой записи (проверено тестами, без сети). Со старым способом остался только отдельный сервис трекера. Циклы перегенерации ограничены (число раундов, на кадр, по деньгам), при исчерпании проект встаёт на паузу с понятной причиной.
- Доставка на GitHub не делалась по решению владельца; перенос в веб-версию ждёт решения по веткам.

## Как воспроизвести

Команды сухих и живых прогонов, лимиты стоимости и ожидаемые результаты — `docs/STAGE_STATUS_REPORT.md` и `docs/ORCHESTRATOR_STATUS_CURRENT.md`.

`scripts/e2e_command_line_ui_server.py` и `scripts/e2e_command_line_ui_smoke.mjs`.
