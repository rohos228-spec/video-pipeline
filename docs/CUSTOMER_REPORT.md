# Управляющий слой (AI-оркестратор): отчёт для заказчика

Обновлён 2026-10-09. Состояние кода: ветка `feature/orchestrator-observe-v1`, коммит `8e0ced0b` (волны W1-W6), Studio v677.
Принцип плана соблюдён: оркестратор не переписывает код проекта. Он работает только с заранее описанными нодами, профилями
моделей и параметрами; серьёзные изменения и утверждение результатов остаются за человеком. Технические детали и команды:
`docs/STAGE_STATUS_REPORT.md`, по нодам: `docs/NODE_COVERAGE.md`, по командной строке: `docs/ACTION_LAYER.md` и
`docs/ORCHESTRATOR_QUICKSTART.md`, по публикации: `docs/PUBLISH_SETUP.md`, реестр платных и живых прогонов: `docs/LIVE_RUNS.md`.

## Как читать этот отчёт

Каждое утверждение помечено классом доказательства. Слово «готово» без класса здесь не используется.

| Класс | Что это |
|---|---|
| U | Юнит-тест: проверена логика, внешних систем нет |
| D | Сухой прогон по настоящему коду шага, подменён только провайдер или сеть |
| L | Живой прогон на настоящем провайдере: дата, потолок денег, строка в `docs/LIVE_RUNS.md` |
| H | Человек проверил и записал: кто, когда, что |

Общая формулировка по умолчанию: подготовлено и проверено на заменителе провайдера (U/D); живого прогона нет (L: нет).
Исключения перечислены в таблице, каждое со ссылкой на строку реестра.

## Что есть сейчас

1. **Наблюдение и аккуратное восстановление нод.** Оркестратор ведёт журнал событий каждой ноды, классифицирует сбои, один раз повторяет
   упавшую текстовую ноду или докачивает уже оплаченное медиа, а решения принимает только из заранее разрешённого списка.
2. **Командная строка (слой действий).** Оператор пишет фразу по-русски, видит план с риском и стоимостью и только потом выполняет;
   платное и стирающее выполняется после подтверждения человеком на сервере. Каталог: 102 действия (чтение 21, локальная запись 36,
   стирающие 44, платное без стирания 1; число сверено с реестром тестом `tests/w5_d09_catalog_test.py`, прошёл 2026-10-09), потолок плана
   200 кредитов, журнал, аварийный стоп.
3. **Контроль изменений.** Предложение, разница, подтверждение человеком, версия, чтение обратно, откат. Меняются промпты и параметры
   нод `plan`, `script`, `split`, `excel_gpt` в заданных пределах; код и логика не меняются никогда.
4. **Журнал проекта и защита.** Единая лента событий проекта на русском (вкладка «Журнал» в панели оркестратора), журнал каждого
   изменяющего запроса оператора, защита платных вызовов (рубильник, потолки, место на диске), резервные копии баз перед миграциями.
5. **Публикация только с отдельным «да» человека.** Подтверждение на каждую площадку, ручное подтверждение результата, защита от дубля.
   Живой площадкой не проверялась (см. таблицу).

## Что ждёт заказчика и менеджера

- **Заказчик (публикация).** Профили MoreLogin, тестовые аккаунты или разрешение на закрытый пост, скриншоты экранов успеха, мастеров, капчи и 2FA, примеры адресов постов, лимиты и правила подписи, ответ «API или браузер» по каждой площадке. Перечень по площадкам: `docs/CUSTOMER_DATA_REQUEST.md`. Инструкция по настройке: `docs/PUBLISH_SETUP.md`.
- **Заказчик (деньги).** Потолки на один прогон, сутки и всё время; выбор основного медиа-провайдера (Kie или Outsee); решение по облачному трекеру; данные Vibecode для калибровки цен.
- **Менеджер.** Какая «v2» и в какую ветку вести PR, общая ли база у v1 и v2, политика серверного подтверждения и журнала, слияние ветки с рабочей веткой заказчика, списки приоритетных фраз и кнопок. Статусы и текст сообщения: `docs/MANAGER_QUESTIONS_STATUS.md`. Состояние веток по локальным данным: ветка `housepc` уже входит в нашу историю, пробное слияние с локальной `origin/main` даёт 53 конфликта.

## Командная строка: что проверено

- **Сквозной путь через HTTP** (`tests/test_e2e_action_layer_http.py`, 20 проверок, без сети, 2026-10-06): фраза, план (модель подменена), подтверждение,
  запуск, результат, журнал, на проекте из 30 кадров. Платное и стирающее без подтверждения не запускаются (403); подтверждение одноразовое;
  подмена шагов после подтверждения отклоняется (`plan_changed`); потолок кредитов не пускает дорогой план (`over_budget`); аварийный стоп
  отклоняет составление и запуск и останавливает идущую фоновую задачу; устаревший план отклоняется (`stale_context`); чужой проект и чужое
  вложение отклоняются; журнал нельзя править. Эти проверки дают класс U/D.
- **Реальный сервер и браузер** (Chrome, 2026-10-06, скриншоты `C:\video-pipeline\_ui_check\cmdline\30…42`; класс H): те же сценарии нажатием
  кнопок в Studio. Платные и стирающие действия в этих прогонах **тестовые** (в памяти, денег не тратят).
- **Не проверялось:** ни одной живой платной генерации через командную строку; поведение на формулировках заказчика; нагрузка.

## Точность планировщика

Измерена на отложенном наборе, под который правила не подгонялись, один раз (строка 11 реестра `docs/LIVE_RUNS.md`): коммит `cc914542`,
127 фраз, **0,85** (108 верно). Первый проход дал 0,795 из-за 14 ошибок транспорта; 11 из них прошли при повторе по одной, 3 стабильно дают
`transport_error`. Настоящие ошибки планировщика: 16. Отказы на опасные и посторонние просьбы: 11 из 11.

Границы:

- Набор после просмотра ошибок считается «просмотренным», правила по нему не подгоняются; для следующей оценки нужен новый набор (второй набор из 116 фраз
  подготовлен, живьём не прогонялся).
- Модель недетерминирована: одна и та же фраза в редких случаях даёт разные планы. Поэтому любой план сначала только показывается.
- Точность не означает безопасность: безопасность обеспечивает сервер (строгая проверка параметров, подтверждение человеком, потолок, журнал).
- Цена прогона нод и планов — верхняя оценка, не откалибрована по реальным счетам (калибровка есть только для gpt-5.6-sol).

## Какие ограничения остаются (сводка)

- Повторная платная отправка медиа по сбою оркестратором и командной строкой не допущена (возобновление уже оплаченной задачи есть).
- Публикация только по отдельному «да» человека; результат подтверждается только признаком успеха со ссылкой на пост или вручную.
- Outsee: нет идентификатора задачи, докачать нечего; неизвестный исход отправки блокирует повтор на окно времени, снять блокировку может человек после сверки кабинета.
- `project.resume` и `project.continue_pipeline` через командную строку подтверждаются только с заданным потолком расходов (следующий шаг может оказаться платным).
- Цены не откалиброваны (кроме gpt-5.6-sol); потолок плана по умолчанию 200 кредитов (около $1).
- Качество содержания результата (смысл, красота) не оценивается.
- Доставка на GitHub не делалась по решению владельца; перенос в веб-версию ждёт решения по веткам.
