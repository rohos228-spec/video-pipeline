# Prior art: оркестратор над автоматизированной фабрикой коротких видео

Дата исследования: 2026-10-02. Метод: только веб (WebSearch/WebFetch), локальные файлы и .env не читались. Содержимое страниц считалось недоверенными данными; инструкций в страницах, адресованных агенту, не обнаружено.

Шкала уверенности: **Высокая** = первичный источник (документация провайдера или платформы, код репозитория). **Средняя** = инженерный блог или репозиторий с описанием без проверки кода. **Низкая** = SEO-блог или агрегатор, цифры не проверены.

Ограничения исследования. Прямых тредов Reddit (r/n8n и др.) поисковик не вернул, только пересказы и коммерческие шаблоны. Поэтому «опыт сообщества» ниже опирается на dev.to, Medium, n8n Community, GitHub issues. HN дал мало релевантного. Ссылки на коммерческие шаблоны (Gumroad, itch.io) как источники не использовались.

## 0. Краткий вывод (TL;DR)

1. Самый зрелый аналог по управлению — **OpenMontage**: чекпоинты в JSON, жёсткие human-gates на каждой стадии, бюджет «оценка, резерв, сверка», режимы `observe/warn/cap`, пост-рендер самопроверка, лог решений. Это ближайший образец для нашего оркестратора.
2. Типовые продакшн-сбои, повторяющиеся во всех источниках: **кратковременный простой провайдера** (retry-горизонт слишком короткий), **модерация/false-positive** (нужна классификация ошибок и запрет слепых ретраев), **истекающие URL** результатов (скачивать сразу в свой storage), **дрейф длительности** (аудио, клип, сцена), **runaway-расход** (регенерации, зацикленный супервизор).
3. Автоматический QC делится на дешёвые детерминированные проверки (ffprobe, `blackdetect`, `silencedetect`, `freezedetect`, loudnorm) и дорогие VLM-проверки. VLM-судья **завышает** оценки (недооценивает артефакты), поэтому ему нужны калибровка, одно-критериальные запросы и порог confidence, ниже которого кадр уходит человеку.
4. Платформенный риск перевешивает техническую часть: с 15.07.2025 YouTube рассматривает полностью автоматизированные шаблонные каналы как «inauthentic content». Финальный human-gate с человеческим редакторским вкладом — это политическое требование, а не только QC.
5. Агент-супервизор должен иметь **механически** ограниченные права (allow-list инструментов, лимит шагов и денег, запрет деструктивных действий без аппрува). Инструкции на естественном языке не защищают: пример Replit.

## 2. Приоритизированные рекомендации по группам узлов

Обозначения: **Adopt** = брать сразу; **Consider** = оценить, внедрить при подтверждённой боли; **Avoid** = не делать.

### 2.1 Текстовые узлы (topic, plan, script)

**Adopt**
- Строгая схема вывода с нормализацией `null` в отсутствующее значение и машинно-проверяемыми полями (F13, F12). Ошибка парсинга считается транзиентной с 1-2 ретраями, затем ручной разбор.
- Проверка длины скрипта относительно целевой длительности ролика (слова в минуту голоса) и санитизация для TTS: числа, акронимы, даты писать словами (Q13, Q10).
- Human-gate на черновике (хук, факты, «зачем ролик существует»): самая высокая отдача на единицу внимания человека (H2). Одновременно это основной аргумент против «inauthentic content» (P1).
- Research-gate: фактические утверждения должны иметь источник, иначе пометка для ревью (F12).
- Fallback-модель LLM на 5xx/429 с записью, какая модель реально отработала (F1, G6).

**Consider**
- Тематическая дедупликация (сходство с последними N темами) как защита от «repetitive» (P1).
- LLM-судья на скрипт по одному критерию на запрос (Q5).

**Avoid**
- Публиковать «чистый» вывод LLM без человеческого вклада; шаблон «скрипт, голос, сток, загрузка» это ровно описанная YouTube цель (P1, P2).
- Кормить LLM нормализованным текстом без возможности обратной трассировки до исходника.

### 2.2 Split на кадры и промпты изображений

**Adopt**
- Хранить для каждого кадра: исходный фрагмент скрипта, промпт, версию промпта, seed/референс (дрейф между стадиями, E2).
- Anchor/reference-подход для консистентности персонажа и стиля вместо одних текстовых суффиксов (Q12).
- Раннее CLIP/VLM-соответствие «промпт-кадр» (Q4), но с одним критерием на запрос и порогом confidence (Q5).
- Pre-compose проверка плана: обещанный формат против реального соотношения статики/движения («slideshow risk», Q3).

**Consider**
- Автоперепись промпта после policy-reject: один нейтральный запасной промпт без попыток обхода фильтра (F8).
- Storyboard-first: сначала дешёвые кадры, затем анимация (C4).

**Avoid**
- Автоматическое «умное» переписывание промптов в цикле до прохождения модерации: это обход защиты, риск аккаунта (F8), и неконтролируемый расход.

### 2.3 Изображения

**Adopt**
- Скачивание результата сразу в собственное хранилище, хэш/размер/декодируемость (E1, E5).
- Классификация ошибок: transient (ретраить с backoff и джиттером) / policy (1 запасной ретрай, затем review) / permanent (стоп) (F3, F4, F8).
- Лимит параллелизма на провайдера из конфига; идемпотентный ключ на кадр (F3, F5).
- Дешёвые автоматические проверки: разрешение, aspect, не одноцветный кадр, дубль через perceptual hash; затем VLM по одному критерию (Q5, Q6).
- Contact sheet для ревью (H1) с ценой и баллами.

**Consider**
- YOLO/hand-детекторы или специализированные оценщики для анатомии (Q7): ценны только если картинки с людьми и руками, и современные модели дают мало ошибок.
- Калибровка VLM по размеченным человеком кадрам (Q6): нужна, если решение «автопропуск» принимается без человека.

**Avoid**
- Доверять VLM-оценке «всё хорошо» без калибровки и без процента кадров, уходящих на человека (Q6).
- Слепые ретраи при ошибках валидации и модерации (F3, F4).
- Подмена изображения сплошным цветом без пометки в статусе: допустимо как fallback (F12), но ролик должен получить флаг «деградировано» и не идти на автопубликацию.

### 2.4 Видео (анимация)

**Adopt**
- Асинхронная модель «submit, poll/webhook, download» с хартбитом, максимальным временем и бюджетом попыток (F9, F11, F5). Статус внешней задачи (request_id) хранить в БД, чтобы пережить рестарт оркестратора.
- Backoff с горизонтом, покрывающим минуты простоя (15/30/60/120 с и более), а не секунды (F1); circuit breaker на провайдера и fallback-провайдер для данного типа клипа (F14, C1).
- Для moderation/RAI: различать детерминированные коды (Child/Celebrity/Sexual) и флейки (Veo audio filter): 3-5 ретраев только для второго класса (F6, F7).
- ffprobe реальной длительности клипа против ожидаемой; разброс более заданного допуска ведёт к ретраю или подгонке (F2, Q4).
- Дешёвые метрики временной консистентности (мерцание, subject consistency, `freezedetect`) как первый фильтр (Q8, Q2).
- Жёсткий cap и per-action аппрув по стоимости до запуска дорогих генераций (C1, C2). Видео самый дорогой узел.

**Consider**
- Storyboard-first: анимировать только утверждённые кадры (C4).
- Over-generation и выбор лучшего дубля только с жёстким лимитом попыток на клип (C5).

**Avoid**
- Бесконечный цикл «регенерировать до хорошего» без счётчика, лимита денег и детекта повторов (C2, C3).
- Хранение провайдерских URL как постоянных ссылок (E1).

### 2.5 Аудио (озвучка, музыка, SFX)

**Adopt**
- Проверка озвучки: ASR (Whisper) против скрипта через CER/WER; forced alignment для субтитров и тайминга сцен (Q9). Порог подбирать на собственных образцах.
- Измерение длительности аудио и сопоставление с планом (E2); подгонка темпа как последний уровень «auto-rescue» (Q4).
- `silencedetect`, пиковый клиппинг, двухпроходный `loudnorm` до -14 LUFS (Q2, Q11).
- Метаданные трека: источник, модель, тариф/лицензия, дата, хэш; запрещённые источники и неоднозначные лицензии блокируют автопубликацию (P6).

**Consider**
- Библиотечная (лицензированная) музыка и SFX как дефолт, AI-музыка только как опция с флагом риска Content ID (P6).
- Словарь произношений для брендов и терминов (Q10).

**Avoid**
- Полагаться на то, что AI-музыка не получит claims (P6); полагаться на устаревшие сведения о лицензиях Suno/Udio без повторной проверки: юридическая ситуация меняется (отключение загрузок у Udio, смена моделей у Suno).
- Whisper-слова как единственный источник таймингов: дрейф (Q9).

### 2.6 Сборка (ffmpeg assemble)

**Adopt**
- Pre-compose gate: все ассеты есть, декодируются, длительности согласованы, формат плана соблюдён (Q3).
- Post-render self-review: ffprobe (кодек, разрешение, `yuv420p`, 9:16, длительность), blackdetect <= ~8%, silencedetect <= ~12%, 4 кадра на VLM/эвристику, наличие субтитров, громкость (Q1, Q3). Ролик не попадает в очередь аппрува, пока self-review не пройден.
- Сборка детерминирована и идемпотентна: одинаковый вход даёт тот же выход; артефакты версионируются, а не перезаписываются (H1).
- Ограничение ресурсов (OOM в FFmpeg, F2): лимит потоков/памяти и таймаут процесса.

**Consider**
- Автоматический «auto-rescue» по уровням (темп аудио, паддинг видео, переписывание) с лимитом попыток (Q4).
- VLM-проверка кадров на оверлеи и читаемость субтитров (Q5, Q6).

**Avoid**
- Проверять «валидность» только по коду возврата ffmpeg: технически корректный, но семантически плохой ролик проходит (Q14).
- Одновременные тяжёлые рендеры без лимита.

### 2.7 Публикация и approval

**Adopt**
- Обязательный человеческий финальный аппрув перед публикацией, с показом точных данных (заголовок, описание, теги, расписание, флаги синтетики) дословно, без запоминания решений и с таймаутом (H3, C2). Аппрув записывается в аудит-трейл; переход в `published` без записанного аппрува отклоняется (H1).
- Загрузка как `private` плюс `publishAt` (планирование на стороне платформы), публикация не «сразу» (P4). Идемпотентный ключ публикации (защита от дублей).
- Заполнение `containsSyntheticMedia` и меток TikTok по правилам; решение принимается по политике (реалистичные люди/сцены), а не на глаз (P3, P5).
- Проверка, что API-проект аудирован, иначе видео молча станут приватными (P4). Мониторинг квоты.
- Лимит частоты и разнообразия публикаций, дедупликация тем, человеческий редакторский вклад как требование стадии (P1).

**Consider**
- Ручное подтверждение первой публикации нового канала/ниши и выборочный аудит остальных, при росте доверия постепенно переходить на выборочный контроль, но не убирать гейт на AI-реалистичных людях и YMYL-темах (P1, P3).
- C2PA/метаданные происхождения (TikTok их читает и может размечать автоматически, P5).

**Avoid**
- Полностью автономная публикация без человека (P1, P2).
- Хранить решение аппрува только в чате/контексте агента, а не в durable-хранилище (G2, G5).
- Дать супервизор-агенту право публиковать/удалять напрямую: только через механически ограниченный инструмент с аппрувом (G2, G3).

### 2.8 Оркестратор и агент-супервизор (сквозное)

**Adopt**
1. Детерминированное ядро (конечный автомат со стадиями, чекпоинты в БД, идемпотентные шаги), агент только советует/классифицирует/эскалирует (G1, F10, F11). Чекпоинт на каждой стадии, возобновление с упавшего шага (F12, H1).
2. Классификатор ошибок как отдельный слой: transient / rate-limit / policy / validation / budget / permanent. Каждому классу своя политика ретраев, бэкоффа и эскалации (F3, F4, F6).
3. Бюджеты в деньгах: оценка, резерв, сверка; режимы `observe/warn/cap`; лимит на ролик, на день, на провайдера; плюс шлюзовый лимит у самого провайдера (C1, C2). Per-action аппрув выше порога.
4. Лимиты на агента: потолок шагов, денег и времени; детект повтора `(tool, args)`; критерий «достаточно хорошо»; эскалация человеку вместо перезапуска (C2, C3, G4, G5).
5. Allow-list инструментов агента; деструктивные и внешние действия (публикация, удаление, смена конфигов/ключей) только через аппрув с дословными аргументами; снапшот и откат при любых правках конфигурации (G2, G3, E7, H3).
6. Лог решений с альтернативами и причинами; сквозной `trace_id`/correlation ID (H1, C7, F14).
7. Метрики (минимум): успех/ошибки по стадии и провайдеру; классы ошибок; число ретраев; доля регенераций; стоимость на ролик и на стадию; латентность p50/p95; глубина очереди и возраст самого старого задания; доля заданий в ручной проверке и время в очереди ревью; доля авто-QC fail по типу проверки; число policy-reject; остаток кредитов/квот провайдеров; доля деградированных (fallback) роликов (H5, C7, C8).
8. Очередь ревью: contact sheet с промптом, ценой и баллами QC; причина попадания в очередь (low confidence, degraded, policy-reject); SLA и авто-экспирация аппрува (H1, Q5, H3).

**Consider**
- Durable-движок (Temporal) если появятся длительные ожидания аппрува и компенсации; для малой фабрики достаточно БД-очереди плюс воркеры (F10, F11).
- Langfuse для трассировки LLM-вызовов, кастомные «generation» для картинок/видео с ценой за единицу (C8).
- Автоматическое «самолечение» только в форме предложения исправления человеку, макс. 2 попытки (E7).

**Avoid**
- Супервизор на LLM без circuit breaker, лимита итераций и бюджета (C3, G4).
- Ограничения, заданные только текстом промпта (G2).
- Использовать Google Sheets или n8n static data как единственное хранилище состояния (H4, F10).
- Тихая подмена провайдера/модели без записи в лог решений (G6).
- Многокритериальные «мега-промпты» для QC-судьи (Q5).

## 3. Пробелы и оговорки

- Прямых примеров Reddit/HN с постмортемами именно фабрик коротких видео найти не удалось; многие «уроки» взяты из блогов отдельных авторов и vendor-кейсов (Kalvium, Kling, Runway-доки). Цифры вроде «89.3% согласия» и «$0.031 за видео» относятся к инструктивным 12-минутным видео, а не к нашему контенту.
- Пороги QC (12% тишины, 8% чёрных кадров, 0.75 confidence, `-35 dB / 3 с`) это стартовые значения из одиночных источников, их нужно калибровать на собственных данных.
- Ограничения Shorts по длительности, квоты YouTube API и условия Suno/Udio меняются; перед внедрением проверять первичную документацию. Квота `videos.insert` в источниках противоречива (1600 единиц против 1 единицы в Video Uploads bucket).
- Юридические вопросы (авторское право AI-музыки, политика платформ) требуют консультации юриста; здесь только обзор публичных источников.
- Для ComfyUI-ссылок от theneuralbase.com и markaicode.com уверенность низкая (агрегаторы, один fetch вернул 403).
