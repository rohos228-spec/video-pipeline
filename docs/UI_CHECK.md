# Визуальная проверка Studio: «Журнал» и «Публикации»

Дата прогона: 2026-10-09. Ветка feature/orchestrator-observe-v1, HEAD 8e0ced0b, Studio v677 (сборка web/out от 2026-10-08, новее исходников панелей).
Проверено на одноразовом стенде в настоящем Chrome (headless, Playwright). Живые площадки, ключи и сеть не использовались.

## Как повторить

1. Сервер на одноразовых данных (папка `%LOCALAPPDATA%\video-pipeline-temp\uicheck`, порт 18999, без ключей провайдеров, Telegram и автопубликация выключены):
   `.venv\Scripts\python.exe scripts\ui_check_journal_publications_server.py` (ждать строку `READY`).
2. Проверка: `node scripts\ui_check_journal_publications.mjs` (скриншоты по умолчанию в `C:\video-pipeline\_ui\run`, переменная `UICHECK_OUT`).
3. Остановить сервер и удалить папку `uicheck`. Сервер удаляет только своё содержимое и только при наличии маркера.

Стенд: проект 1 (собран, финальное видео, 5 площадок в разных состояниях, 164 записи в журнале из operator_audit, spend_ledger,
notification_log, publications, observation_events) и пустой проект 2. Сид идёт через публичные функции модулей.
Состояние стенда меняется самой проверкой (кнопки пишут решения), поэтому перед каждым прогоном сервер перезапускают.

## Итог: 60 из 69 проверок прошли. Падения ниже, все они про текст и раскладку, а не про запросы

Работает: обе панели рисуются, русские подписи состояний, фильтры («Деньги», «Ошибки», важность, период), поиск с задержкой (один запрос),
«Показать ещё» (cursor), экспорт CSV и JSON (с фильтрами, BOM, осмысленное имя файла), ошибка 500 с «Повторить», пустое состояние,
кнопки публикаций шлют верные запросы с заголовком `X-VP-Operator` и показывают результат, отказ сервера (409) показывается русским текстом.
Ошибок страницы (pageerror) нет. Консоль: 404 на `/api/fleet/transfers/active` и `/api/projects/2/observations/launch-options`
(вне этих панелей); 409 и 500 в консоли вызваны самой проверкой (подмена ответов).

## Найденные дефекты (продуктовый код не менялся)

1. Серьёзно, телефон 390px. В настоящей раскладке Studio панель оркестратора (с «Публикациями» и «Журналом») сжимается до ~16px и
   не читается: боковая колонка проектов и правый инспектор имеют фиксированную ширину, центральная колонка остаётся без места.
   Горизонтального скролла у страницы нет (скрыт overflow), но пользоваться панелью нельзя. `web/src/app/page.tsx:94,105`
   (`flex ... <main className="relative min-w-0 flex-1 overflow-hidden">`), ширина колонки `web/src/components/sidebar/project-sidebar.tsx:496`.
   Сами компоненты в колонке 390px помещаются без выхода за границы (проверено подстановкой ширины), то есть чинить надо раскладку Studio.
2. Журнал показывает сырой вид события в бейдже: «Событие «node_error»», «node_start», «node_end», «retry_scheduled».
   Сервер отдаёт для событий наблюдения `kind` = сырой вид (`app/services/timeline.py:246`), а `KIND_LABELS_RU` на странице знает только 10 видов
   (`web/src/lib/journal-view.ts:54-65`, запасной вариант `kindLabel` на строке 81). Заголовок строки при этом русский («Ошибка исполнителя»).
   Фильтр по виду для этих событий недоступен (в списке видов их нет).
3. В каждой строке журнала торчит служебное имя таблицы: «источник spend_ledger / operator_audit / notification_log / publications / observation_events».
   `web/src/components/orchestrator/journal-section.tsx:39`.
4. Публикации: коды показаны латиницей как есть: «Код: confirm_timeout», «Код: not_logged_in», «Код: publish_disabled»
   (`web/src/components/orchestrator/publications-section.tsx:120`). После ручного подтверждения у успешной площадки жёлтая строка «Код: manual_confirmed»
   (код записывается в `app/services/publications_store.py:527`), после «Не опубликовано» — «Код: manual_not_published».
5. Публикации: действие вручную показано сырым словом: «Вручную: confirm · operator», «Вручную: mark_failed · operator · …»
   (`publications-section.tsx:121`). Имя оператора всегда просто «operator»: Studio не передаёт `X-Action-Layer-Operator`, поэтому в журнале и в
   `publication_manual_actions` нельзя отличить людей (`app/web/routers/publications.py:41`).
6. Публикации: после «Разрешить публикацию» при выключенной автопубликации баннер сверху пишет «Публикация идёт.», а сообщение внизу говорит
   «сейчас ничего не публикуется». Состояние `publishing` берётся из `derive_project_state` без учёта флага автопубликации
   (`app/services/publications_store.py:611`), текст — `publications-section.tsx:26`. Он же скрывает «Ждёт проверки человека», пока есть разрешённая площадка.
7. Публикации: сообщение результата («Подтверждение записано…») остаётся при переключении на другой проект, в пустом проекте 2 видно чужое сообщение.
   `note` не сбрасывается при смене `projectId` (`publications-section.tsx:44`, эффект на строке 59 сбрасывает только опрос). Так же `facts` предыдущего проекта
   живёт до первой загрузки.
8. Журнал: ручная пометка человека «Не опубликовано» попадает в ленту как красная «Публикация не удалась · ошибка manual_not_published»
   (`app/services/timeline.py:432-440`, `_b_publication`): решение человека выглядит как сбой и входит в счётчик «ошибок».
9. Журнал: в строках действий оператора виден шаблон маршрута «POST /api/projects/{project_id}/publications/{platform}/confirm-manual»
   (`timeline.py:414-421`); код ответа в тексте не показан (только «выполнено»).
10. Журнал: 164 строки выводятся одним списком без внутренней прокрутки, панель вырастает до ~14000px (`journal-section.tsx:228`); на странице
    это длинная простыня, поиск по странице и «Скачать CSV» спасают, но «Показать ещё» подгружает по 100 строк в тот же список.
11. «Площадка не начиналась» (likee) и «пропущено» (vk_clips) оба показывают «Подтвердить вручную» только когда есть строка в журнале; у likee кнопок
    ручного подтверждения нет, только «Разрешить публикацию». Это по замыслу (`can_confirm_manual` требует строки), отмечено для ясности.

## Что не проверено

Реальные площадки, MoreLogin, включение автопубликации, Telegram, большие объёмы (50000 строк экспорта), другие браузеры, реальный телефон
(проверялась эмуляция ширины 390px в Chrome), длинный журнал с реальными кодами событий наблюдения, кроме тех пяти, что засеяны.

## После исправлений (2026-10-09, та же ветка, поверх HEAD 8e0ced0b и W7)

Стенд и скрипт те же (`scripts/ui_check_journal_publications_server.py`, `scripts/ui_check_journal_publications.mjs`), Studio пересобрана
(`cd web && npx next build`, экспорт в `web/out`), чистый сид, скриншоты в `C:\video-pipeline\_ui\run_after`, полный вывод скрипта там же
(`check-output.log`, `results.json`). Итог: **78 из 78 проверок прошли** (было 60 из 69; к 69 прежним проверкам добавлено 9 новых: выезжающие колонки
на телефоне и неизменность десктопной раскладки). pageerror нет. Сетевых ошибок в консоли прежние: 404 на `/api/fleet/transfers/active` и
`/api/projects/2/observations/launch-options` (вне этих панелей), 409 и 500 вызваны самой проверкой (подмена ответов). Сервер и браузер остановлены,
папка `uicheck` удалена.

Что исправлено (номера как выше):

1. Телефон 390px: `web/src/app/page.tsx`. До 768px колонка проектов и инспектор не делят экран с центром: над рабочей областью полоса с кнопками
   «Проекты» и «Инспектор», колонки выезжают поверх центра (ширина `min(85vw, 320px)`), подложка закрывает их, выбор проекта закрывает колонку. Панель
   оркестратора на 390px теперь шириной 366px (было ~16px), горизонтального скролла нет. Десктоп 1500px без изменений: проекты 304px, инспектор 320px,
   центр 876px, полосы кнопок нет. Новый хук `web/src/hooks/use-media-query.ts`.
2. Журнал: подпись вида записи больше не берёт сырой вид («Событие «node_error»» убрано). События наблюдения подписаны «Событие наблюдения», незнакомое
   «Прочее», добавлены «Пробел журнала» и фильтр «Событие наблюдения» (сервер принимает имя источника в `kinds`). Заголовок строки берётся из серверного
   `title_ru`; запасной заголовок сервера больше не содержит сырой вид. «источник spend_ledger» заменён названием («источник: учёт расходов»), для
   всех 13 источников есть русские названия. Файлы: `web/src/lib/journal-view.ts`, `journal-section.tsx`, `app/services/timeline.py`.
3. Публикации: коды причин показаны русской фразой («Причина: Площадка не подтвердила публикацию вовремя…»), служебные `manual_confirmed` и
   `manual_not_published` не показываются как сбой. «Вручную: подтверждено вручную как опубликованное · оператор». Новый `web/src/lib/publication-text.ts`.
   Заголовок `X-Action-Layer-Operator` Studio не передаёт: имени оператора из входа в Studio нет (вход есть только в сетевой панели флота), выдумывать
   имя нельзя. Поэтому сервер пишет `operator`, панель показывает «оператор»; если имя придёт заголовком (`operator:<имя>`) или кнопкой Telegram
   (`telegram:<id>`), оно будет показано.
4. «Разрешить публикацию»: одно честное сообщение. Сервер (`publications.py`, `_approve_message`) говорит «Разрешено и поставлено в очередь», либо
   «Разрешено, но публикация выключена настройкой», либо «шаг публикации уже идёт и учтёт разрешение»; верхняя строка панели при выключенной
   автопубликации больше не пишет «Публикация идёт», а «ждёт проверки человека» не прячется за разрешённой площадкой.
5. Сообщение результата, ошибка, факты и введённый текст сбрасываются при смене проекта; запоздавший ответ прошлого проекта отбрасывается.
6. «Не опубликовано» (решение человека) в ленте: важность «обычное», подпись «Закрыто человеком: публикация помечена как «не опубликовано»», в счётчик
   ошибок не входит; ручное подтверждение подписано «Подтверждено человеком вручную». Настоящий сбой остаётся ошибкой, с русской причиной (`app/services/timeline_ru.py`).
7. Строка оператора: настоящий путь (`/api/projects/1/publications/yt_shorts/confirm-manual`) и «код ответа 200»; шаблон `{project_id}` нигде не виден
   (ни в тексте, ни в «ссылке»).
8. Длинный журнал: список строк листается в своём окне (до 60% высоты экрана), строки с `content-visibility: auto`, при смене фильтров список
   возвращается наверх; панель больше не вырастает на тысячи пикселей.

Кроме того: `POST /api/hitl/{id}/decision` на запросе вида `approve_publish` отвечает 409 «Решение по публикации принимается только на странице
публикаций или кнопкой в Telegram», запрос не меняется (`app/web/routers/hitl.py`).

Проверки без браузера: `tests/w7_b_ui_texts_test.py` (16 тестов), вместе с `tests/w3_*`, `tests/w6_1_*`, `tests/w7_*`: 280 прошли; `npx tsc --noEmit`
