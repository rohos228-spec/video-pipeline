# Публикация: настройка для оператора заказчика

Для кого: человек, который отвечает за аккаунты в соцсетях и запускает публикацию из Studio. Здесь шаги настройки: профили MoreLogin по площадкам, признаки успеха, лимиты, «да» на каждую публикацию, проверка командой `preflight`, действия при капче и 2FA.

Состояние на 2026-10-09 (ветка `feature/orchestrator-observe-v1`, коммит `8e0ced0b`, Studio v677); это снимок, живых публикаций после него не делалось, числа тестов: `docs/TESTING.md`. Честно, до начала:

- Публикация **не проверялась ни на одной живой площадке** (класс L: нет). Проверены только тесты на подмене браузера и базы (класс U/D): 188 тестов публикации и каталога действий прошли 2026-10-09 (`tests/w6_*`, `tests/test_w1_6_publish_safety.py`, `tests/w5_5_publish_action_test.py`, `tests/w5_d09_catalog_test.py`); прогон шёл на рабочей копии коммита `8e0ced0b`, в которой на тот момент лежали ещё не закоммиченные правки другой роли (Telegram-кнопки публикации, см. раздел 6, пункт 6).
- Признаки успеха по умолчанию **пусты**. Пока вы их не задали и не проверили на своём аккаунте, итог любой публикации будет «не подтверждено» (`unconfirmed`), а проект не станет «опубликован».
- Автопубликация выключена по умолчанию (`SOCIAL_PUBLISH_ENABLED=false`). Её включаете вы сами, после пунктов 1-4 ниже.
- Селекторы страницы загрузки в коде (поле файла, поле подписи, кнопка «Опубликовать») это догадки, на живых интерфейсах не калиброваны. У YouTube Studio и Instagram есть пошаговые мастера (дальше, видимость, метка «для детей» и т. п.), в коде их обработки нет. Пока их не доработают по вашим скриншотам (`docs/CUSTOMER_DATA_REQUEST.md`), на этих площадках публикация, скорее всего, не дойдёт до конца и остановится с кодом `selector_not_found` или `processing_timeout`. Это ожидаемая безопасная остановка, а не сбой настройки.
- Пароли, куки, коды 2FA нигде не вводятся и не хранятся. Вход в аккаунты вы делаете вручную в профиле MoreLogin.

---

## 1. Что нужно заранее

1. MoreLogin запущен на том же компьютере, что и Studio. Его локальный API по умолчанию отвечает на `http://127.0.0.1:40000`. Если у вас другой порт, задайте переменную окружения `MORELOGIN_API_URL`.
2. Для каждой площадки есть профиль MoreLogin, в котором вы **вручную вошли** в аккаунт этой площадки. Один профиль на все площадки или отдельный на каждую, решаете вы; код умеет и то и другое.
3. Номера (идентификаторы) профилей из MoreLogin под рукой. Они считаются чувствительными: в журналах и сообщениях показываются только последние 4 символа, в письмах и чатах их присылать не нужно.
4. Если Local API вашего MoreLogin требует ключ (App ID и Secret), код **этого не поддерживает**: запросы к API уходят без ключа. Сообщите нам, нужен ли он (вопрос есть в `docs/CUSTOMER_DATA_REQUEST.md`).

## 2. Шаг 1. Файл `data/publish_accounts.json`

Файл лежит в папке данных Studio: `data/publish_accounts.json` (если задана переменная `DATA_DIR`, то в ней). Его нет в репозитории и в сборке, вы создаёте его сами. Тот же JSON можно положить в переменную окружения `PUBLISH_ACCOUNTS_JSON`: она читается после файла и перекрывает его ключи по площадкам.

Права и сохранность: файл не содержит паролей, но содержит номера профилей. Не публикуйте его и не присылайте целиком.

Допустимые коды площадок строго такие: `tiktok`, `yt_shorts`, `ig_reels`, `vk_clips`, `likee`. Другое имя или лишнее поле даёт ошибку («неизвестная площадка», «неизвестные поля …»), публикация при этом не начинается (код `accounts_config_invalid`, текст ошибки не содержит значений из файла).

### Как выбирается профиль

- Если хотя бы у одной площадки задан `profile_id`, включается режим «по площадкам». Площадка без своего `profile_id` получает отказ `profile_missing`: чужой профиль **не подставляется**, чтобы пост не ушёл не в тот аккаунт.
- Если файла и переменной нет совсем, работает старый режим: один профиль на все площадки из переменной окружения `MORELOGIN_PROFILE_ID`.
- Профиль после работы **не закрывается** (браузер оператора остаётся открытым). Закрывать его автоматически можно только явной настройкой `MORELOGIN_STOP_ON_EXIT=1`; делайте это только для профиля, который поднимает сам робот.

### Все допустимые ключи площадки

Ключей, которых нет в таблице, код не принимает. Названия ключей с `pass`, `pwd`, `token`, `secret`, `cookie`, `api_key`, `authorization`, `session`, `credential`, `otp`, `2fa_code` отклоняются при загрузке как секреты (проверяются имена, не значения).

| Ключ | Тип | Что делает |
|---|---|---|
| `profile_id` | строка или число | Номер профиля MoreLogin для этой площадки. |
| `account_label` | строка | Подпись аккаунта для вас и журнала (без секретов). Если пусто, показывается «площадка (профиль …1234)». |
| `enabled` | true/false | `false`: площадка пропускается без записи в журнал. Читайте предупреждение в разделе 8, пункт 1. |
| `region` | строка | Справочное поле для вас (страна/регион профиля). Кодом не используется. |
| `upload_url` | строка | Свой адрес страницы загрузки вместо адреса по умолчанию (например, студия нужного канала YouTube). |
| `max_per_day` | целое ≥ 1 | Лимит нажатий «Опубликовать» на площадке за скользящие 24 часа. |
| `window_hours` | `[с, до]`, часы 0-24 | Разрешённое окно по местному времени компьютера, например `[10, 22]`; `[22, 6]` значит через полночь. Равные числа недопустимы. |
| `caption_limit` | целое ≥ 1 | Максимальная длина итоговой подписи (текст + суффикс + хэштеги). |
| `title_limit` | целое ≥ 1 | Максимальная длина заголовка (YouTube). Заголовок берётся из первой строки подписи. |
| `on_overflow` | `reject` или `truncate` | Подпись длиннее лимита: `reject` отказывает (код `platform_limit`, ничего не нажимается), `truncate` обрезает основной текст и сохраняет суффикс и хэштеги. По умолчанию `reject`. |
| `hashtags` | список строк | Хэштеги, которые добавляются в конец подписи (без повторов с теми, что уже есть в тексте). |
| `caption_suffix` | строка | Текст в конце подписи (например, обязательная метка ИИ-контента, если её требует площадка). |
| `hashtag_separator` | строка | Чем отделять суффикс и хэштеги от основного текста и друг от друга. По умолчанию два перевода строки (пустая строка), в JSON `"\n\n"`. |
| `title_selectors` | список селекторов | Где поле заголовка. Если не задано, заголовок не заполняется. |
| `processing_timeout_s` | число ≥ 0 | Сколько секунд ждать конца загрузки и обработки ролика до кнопки «Опубликовать». По умолчанию 300. |
| `processing_busy_selectors` | список селекторов | Признаки «идёт загрузка/обработка» (пока видны, кнопка не нажимается). |
| `processing_done_selectors` | список селекторов | Признаки «готово» (если заданы, без них кнопка не нажимается). |
| `logged_in_selectors` | список селекторов | Элементы, видимые только после входа. Если заданы и не найдены за ~4 секунды, площадка считается «не вошли». |
| `login_selectors`, `login_url_markers` | списки | Признаки страницы входа (по умолчанию: поле пароля; адрес содержит `/login`, `/signin`, `accounts.google.com` и т. п.). |
| `captcha_selectors`, `two_factor_selectors` | списки | Признаки капчи и запроса кода 2FA. По умолчанию заданы общие догадки (iframe капчи, поле одноразового кода, тексты «я не робот», «код подтверждения»). |
| `error_selectors` | объект: код отказа → список | Где площадка пишет ошибку. Допустимые коды: `upload_failed`, `platform_limit`, `rate_limited`, `rejected` и остальные из раздела 7. По умолчанию есть общие догадки по тексту. |
| `success_selectors` | список селекторов | Признак успеха на странице после клика. **По умолчанию пусто.** |
| `success_url_markers` | список строк | Куски адреса страницы, который появляется после публикации. **По умолчанию пусто.** |
| `post_url_regex` | регулярное выражение | Как должна выглядеть ссылка на настоящий пост (см. шаг 3). |
| `post_link_selector` | селектор | Элемент, у которого в `href` лежит ссылка на пост. |
| `confirm_timeout_s` | число ≥ 0 | Сколько секунд ждать признака успеха после клика. По умолчанию 8. |
| `verify_ok_selectors`, `verify_gone_selectors`, `feed_url`, `feed_item_selector` | списки/строки | Настройки независимой проверки поста и сверки с лентой. **Сейчас кодом публикации не вызываются** (функции есть, но шаг публикации их не использует). Задавать бессмысленно. |

В блоке `defaults` допустимы только `pause_s` (пауза между площадками, секунды, по умолчанию 3) и `jitter_s` (случайная добавка к паузе, по умолчанию 0).

Что **нельзя** настроить через файл: селекторы поля файла, поля подписи и кнопки «Опубликовать». Если площадка поменяла интерфейс и они сломались, это правка кода (получите отказ `selector_not_found`).

Если в окружении задан `PUBLISH_ACCOUNTS_JSON`, он накладывается на файл по ключам площадки: ключи из переменной заменяют такие же ключи из файла, остальные остаются.

## 3. Шаг 2. Проверка командой preflight

`preflight` открывает страницу площадки в профиле MoreLogin и сообщает состояние. Он **ничего не загружает, не вводит и не нажимает**.

Из корня репозитория (PowerShell):

```powershell
.venv\Scripts\python.exe -m app.bots.publishers preflight
.venv\Scripts\python.exe -m app.bots.publishers preflight tiktok yt_shorts
```

Без названий проверяются все пять площадок, с названиями только указанные. Studio для этого запускать не обязательно, нужен запущенный MoreLogin.

Вывод: по строке на площадку в виде `площадка: OK` или `площадка: код отказа`, затем подпись аккаунта и русский текст. Примеры кодов:

| Код | Что значит | Что делать |
|---|---|---|
| `OK` | Страница открылась, вход есть, капчи и запроса 2FA не видно. | Можно идти дальше. |
| `profile_missing` | Для площадки не задан `profile_id` (или нет файла и `MORELOGIN_PROFILE_ID`). | Допишите профиль в `publish_accounts.json`. |
| `profile_unavailable` | MoreLogin не отвечает или профиль не запустился. | Запустите MoreLogin, проверьте порт (`MORELOGIN_API_URL`) и номер профиля. |
| `page_unavailable` | Страница площадки не открылась или открылся чужой сайт. | Проверьте интернет и профиль. |
| `not_logged_in` | В профиле нет входа. | Войдите вручную в этом профиле MoreLogin и повторите. |
| `captcha`, `two_factor` | Площадка показывает капчу или просит код. | Пройдите вручную, см. раздел 6. |
| `accounts_config_invalid` | Ошибка в `publish_accounts.json`. | Исправьте по тексту ошибки. |

Важно знать:

- `preflight` переводит уже открытую вкладку этой площадки на страницу загрузки. Не оставляйте в этом профиле несохранённую работу на той же площадке.
- Успешный `OK` значит только «страница открыта, видимых признаков проблемы нет». Он не доказывает, что публикация пройдёт, и не проверяет признаки успеха.
- Без `logged_in_selectors` проверка входа грубая: по адресу страницы входа и по полю пароля. Лучше задать `logged_in_selectors`.
- Команду `python -m app.bots.publishers recon <площадка>` (вывод кандидатов в селекторы страницы загрузки) разработчик использует при калибровке. Она берёт только старый общий профиль из `MORELOGIN_PROFILE_ID`, не файл по площадкам.
- На 2026-10-09 `preflight` на настоящем MoreLogin и живых площадках **не запускался**; проверена логика на подмене страницы (`tests/w6_2_accounts_test.py`).

## 4. Шаг 3. Признаки успеха публикации

Зачем: после клика система должна **доказать**, что пост появился, и получить ссылку на него. Пока доказательства нет, итог «не подтверждено», автоповтора нет, дальше решает человек. Это защита от дубля, но без признаков успеха ни один проект не дойдёт до «опубликован».

Как система решает, что пост опубликован. Нужны **оба** условия:

1. Сработал признак успеха: адрес страницы содержит один из `success_url_markers` или на странице есть элемент по одному из `success_selectors`.
2. Найдена ссылка на пост и/или идентификатор поста (иначе итог «признак успеха есть, ссылки нет», то есть тоже не подтверждено).

Как задать:

1. Сделайте **тестовую публикацию вручную** в закрытом режиме (YouTube: «Доступ по ссылке» или «Закрытый»; TikTok: «Только я»; VK: «только для меня»; для Instagram и Likee нужен тестовый аккаунт, непубличного поста там может не быть). После нажатия «Опубликовать» не закрывайте страницу.
2. Откройте инструменты разработчика браузера (F12) в окне профиля MoreLogin. Найдите:
   - что именно появляется на странице при успехе (окно «Видео опубликовано», зелёное уведомление): скопируйте для него устойчивый селектор в `success_selectors`;
   - во что меняется адрес страницы после публикации: общую устойчивую часть адреса в `success_url_markers`. Не берите кусок, который есть и на странице загрузки: такой маркер срабатывает до публикации;
   - как выглядит ссылка на опубликованный пост: напишите выражение в `post_url_regex`. Идентификатор поста берётся из группы `(?P<id>…)` или из первой группы. Если ссылка лежит в элементе страницы, укажите его в `post_link_selector`.
3. Форма записи (значения-заглушки, подставьте свои):

```json
"tiktok": {
  "profile_id": "ID_ПРОФИЛЯ_TIKTOK",
  "success_selectors": ["<селектор окна «Видео опубликовано»>"],
  "success_url_markers": ["<устойчивая часть адреса после публикации>"],
  "post_url_regex": "^https://example\\.invalid/video/(?P<id>[0-9]+)",
  "post_link_selector": "a[href*='/video/']",
  "confirm_timeout_s": 20
}
```

   Обратите внимание на двойной обратный слэш: в JSON его нужно удваивать. Выражение проверяется при загрузке; если оно не компилируется, вы получите `accounts_config_invalid`.

4. **Всегда задавайте `post_url_regex`.** Без него ссылкой на пост считается любой новый адрес страницы, отличный от страницы загрузки, и слишком широкий признак успеха может дать ложное «опубликовано».
5. Проверка на вашем аккаунте: одна публикация в закрытом режиме, затем **вы сами открываете полученную ссылку** и убеждаетесь, что это ваш пост. Только после этого признаки можно считать рабочими. Скриншот результата система сохраняет в `data/publications/<номер проекта>/<площадка>.png`; приложите его, когда присылаете результат нам.
6. Тестовый пост после проверки удалите на площадке вручную. Система удалять посты не умеет.

Что происходит, если признаки не заданы или не сработали: итог «не подтверждено» (`no_success_marker`), в Studio состояние «не подтверждено, ждёт проверки человека», в Telegram сообщение. Клик уже мог состояться, поэтому автоповтора **нет**.

## 5. Шаг 4. Лимиты, окно, подпись

- **Лимит в сутки** (`max_per_day`): считается по журналу публикаций, нажатия за последние 24 часа по этой площадке (по всем проектам вместе). При превышении площадка не берётся в работу, публикация **переносится** (статус `skipped`, код `daily_limit`, указано время, раньше которого повтор бессмыслен). Перенос не считается ошибкой и не ждёт человека.
- **Окно** (`window_hours`): по местному времени компьютера, где работает Studio. Вне окна публикация переносится (`outside_window`).
- **Пауза между площадками**: `defaults.pause_s` + случайная добавка до `defaults.jitter_s`.
- **Подпись**: берётся из темы проекта (до 2200 символов), одна и та же для всех площадок. Для каждой площадки к ней добавляются `caption_suffix` и `hashtags` из конфига и проверяется `caption_limit`. Пустая подпись или подпись, которая не поместилась при `on_overflow: reject`, останавливает публикацию **до клика**. После заполнения поле читается обратно: не совпало, клика нет (`caption_not_filled`). Если для YouTube заданы `title_selectors`, заголовок берётся из первой строки подписи.
- **Отложенная публикация средствами платформы** (расписание на стороне площадки) не реализована. Есть только окно и лимиты выше.

## 6. «Да» человека на каждую публикацию

Робот не нажимает «Опубликовать» без вашего отдельного «да». Правила (проверены тестами U/D, на живой площадке нет):

1. «Да» выдаётся **на одну площадку** для **одного файла** (sha256 финального видео) и **одной подписи** (sha256 текста). Изменили тему проекта или пересобрали видео: прежнее «да» недействительно, нужно новое.
2. «Да» **одноразовое**. Оно тратится прямо перед кликом. Если после этого что-то пошло не так, второго клика без нового «да» не будет.
3. Режим автопродвижения проекта (`auto_mode`) и `HITL_AUTO_APPROVE` «да» не создают. Это проверяется тестами.
4. Где нажать (Studio, коммит `8e0ced0b`): открыть проект, панель «Оркестратор», раздел «Публикации», у нужной площадки кнопка **«Разрешить публикацию»**. До этого раздел показывает файл (первые символы sha256), подпись и состояние каждой площадки. Для кнопок нужен токен оператора (страница Studio получает его сама; если видите «Нужен токен оператора», обновите страницу).
5. Публикация пойдёт, только если включено `SOCIAL_PUBLISH_ENABLED=true`. При `false` «да» запишется, но ничего не отправится, а проект получит пометку «публикация пропущена» (не «опубликован»).
6. Telegram: в коммите `8e0ced0b` бот присылает **текст** («публикация не начата, ждёт вашего подтверждения», итоги, «нужен человек»), но **кнопок «да» в Telegram нет**. Примечание на момент написания: в рабочей копии репозитория (не закоммичено, не проверено) другая роль добавляет кнопки «Разрешить публикацию»/«Не публиковать» в Telegram. Когда это будет закоммичено и проверено, этот пункт нужно обновить.
7. Через командную строку (слой действий) есть действие `publish.send`: уровень «стирающее», каждый план требует отдельного подтверждения. Оно только ставит шаг публикации в очередь; «да» на площадки из пункта 4 всё равно нужно. Управляемый (агентский) режим публикацию не запускает.

Состояния площадки в разделе «Публикации»:

| Что видите | Значение | Что делать |
|---|---|---|
| ещё не начиналось | Записи нет. | Выдать «да». |
| намерение записано, клика не было | Шаг взял площадку, но клика ещё не было. | Подождать окончания шага (занятость до 15 минут). |
| пропущено (автопубликация выключена) | `SOCIAL_PUBLISH_ENABLED=false`. | Включить флаг после preflight и калибровки. |
| сбой до клика, ничего не опубликовано | Остановка до нажатия (капча, нет профиля, подпись и т. п.). | Устранить причину по коду; для кодов, требующих человека, см. раздел 7. Для остальных автоповтор возможен до 3 попыток с вашим «да». |
| не подтверждено, ждёт проверки человека | Клик был, признак успеха не найден. | Открыть площадку, проверить (раздел ниже). |
| сбой после клика, автоповтора не будет | Исключение после клика. | Проверить площадку вручную (раздел ниже). |
| опубликовано | Подтверждено признаком успеха со ссылкой/ID или вами вручную. | Ничего. |

### Ручное подтверждение

Для «не подтверждено» и «сбой после клика» **сначала откройте площадку и проверьте, есть ли пост.** Затем в разделе «Публикации» у площадки:

- **«Подтвердить вручную»**: пост есть. В поле введите ссылку на пост (начинается с `https://`) либо причину не короче 5 символов. С ссылкой запись станет «опубликовано» со ссылкой; без ссылки пометка «подтверждено вручную» без адреса.
- **«Не опубликовано»**: поста нет. Причина не короче 5 символов обязательна. Площадка закрывается, повторного клика система не делает.

Оба действия фиксируются: кто, когда, что было до, ссылка/причина (журнал ручных действий и журнал действий оператора). Клик по площадке они не повторяют.

## 7. Что делать при капче, 2FA, потере входа

Система распознаёт капчу, запрос кода 2FA и страницу входа до загрузки файла (preflight страницы) и во время ожидания обработки. Тогда:

- Публикация на этой площадке **останавливается**, автоповтора нет, в Telegram приходит «Нужен человек» с причиной, проект получает состояние «ждёт проверки человека».
- Если остановка случилась **до клика**, ничего не опубликовано.

Что делает оператор:

1. Откройте профиль MoreLogin этой площадки. Войдите заново, пройдите капчу или введите код 2FA **вручную**. Код 2FA и пароль в Studio, чат и конфиг не вводятся.
2. Убедитесь командой `preflight <площадка>`, что вернулось `OK`.
3. В разделе «Публикации» нажмите «Не опубликовано» (причина, например, «капча, прошёл вручную») для этой площадки.
4. Повтор публикации. **Известное ограничение:** кнопки «повторить после остановки человеком» в панели нет. «Не опубликовано» без флага повтора закрывает площадку для этого файла. Чтобы снова разрешить публикацию, специалист должен вызвать тот же запрос с признаком `allow_republish` и затем выдать новое «да» кнопкой «Разрешить публикацию»:

   `POST /api/projects/{id}/publications/{площадка}/mark-failed` с телом `{"sha256": "<sha256 файла>", "reason": "<причина не короче 5 символов>", "allow_republish": true}` и заголовком `X-VP-Operator: <токен оператора>` (токен выдаёт страница Studio через `GET /api/auth/operator-token`).

   Этот путь не проверялся на живой системе. Если вам неудобно, переопубликовать можно вручную на площадке и нажать «Подтвердить вручную» со ссылкой.

Коды отказов, которые вы можете увидеть (тексты на русском есть в Studio, в Telegram и в журнале):

| Код | Остановка без автоповтора | Смысл |
|---|---|---|
| `profile_missing`, `profile_unavailable` | `profile_missing` да | Нет профиля / MoreLogin недоступен. |
| `not_logged_in`, `captcha`, `two_factor` | да, зовут человека | Нет входа, капча, запрос кода. |
| `rate_limited`, `rejected` | да | Площадка ограничила частоту / отклонила публикацию. |
| `page_unavailable` | нет | Страница не открылась. |
| `selector_not_found` | нет | Не найден элемент страницы (поле файла, подписи, кнопка); интерфейс мог измениться. |
| `upload_failed`, `processing_timeout` | нет | Файл не загрузился / обработка не завершилась за отведённое время, клик не делался. |
| `platform_limit`, `daily_limit`, `outside_window` | нет | Подпись не по лимитам площадки / лимит в сутки / вне окна: перенесено или остановлено до клика. |
| `caption_empty`, `caption_field_missing`, `caption_fill_failed`, `caption_not_filled` | нет | Подпись пуста / поле не найдено / не заполнилось: клика не было. |
| `click_not_allowed` | нет | Журнал публикаций не разрешил клик (нет вашего «да» или площадку уже обрабатывает другой запуск). |
| `no_success_marker`, `confirmed_without_url` | **да** (клик был) | Нажато, признак успеха не найден / ссылка не получена: проверьте площадку вручную. |
| `exception_before_click` | нет | Сбой до нажатия. |
| `exception_after_click` | **да** (клик был) | Сбой после нажатия: проверьте площадку вручную. |
| `accounts_config_invalid` | да | Ошибка в `publish_accounts.json`. |

«Нет автоповтора до клика» значит: безопасный повтор возможен, до 3 попыток на площадку и файл, и каждый раз нужно ваше новое «да». После клика автоповтора нет никогда.

## 8. Известные ограничения (по чтению кода, живыми прогонами не проверялись)

1. **Статус «опубликован» проект получает, только когда подтверждены все пять площадок реестра.** Я проверил это расчётом функции `derive_project_state` (3 подтверждённых из 5 дают `awaiting_approval`). Если вы пользуетесь не всеми пятью, проект останется в статусе «собран» с пометкой «нужно подтверждение», хотя нужные площадки подтверждены. Закрыть неиспользуемую площадку кнопкой «Не опубликовано» нельзя, пока для неё нет записи в журнале. `enabled: false` в конфиге пропускает площадку без записи и этого не исправляет. Не выдавайте «да» на неиспользуемую площадку. Это дефект/доработка на стороне разработки (вопрос к вам: как должен считаться «опубликован»).
2. Независимая проверка поста (открыть ссылку позже) и сверка с лентой перед повтором в коде есть, но шагом публикации **не вызываются** (ключи `verify_*`, `feed_*` ни на что не влияют).
3. Мастера YouTube Studio и Instagram (несколько экранов подряд, метка «для детей», видимость, AI-метка) в коде не реализованы; на TikTok и VK раскрытие контента и метки ИИ не заполняются. Эти поля нужно разобрать по вашим скриншотам.
4. Ключ MoreLogin API (App ID/Secret) не поддерживается.
5. Расписание на стороне платформы не поддерживается.
6. Один запуск обходит площадки подряд в одном процессе; параллельной публикации нет.
7. Первую настоящую публикацию делаем вместе: сначала закрытый пост на тестовом или своём аккаунте, затем удаление, и только потом боевой пост с вашим «да» на этот пост.

## 9. Чек-лист оператора

1. MoreLogin запущен, в каждом профиле вручную выполнен вход.
2. Создан `data/publish_accounts.json` (раздел 2), проверен на ошибки: любая ошибка формата покажется в `preflight` кодом `accounts_config_invalid`.
3. `preflight` по всем нужным площадкам даёт `OK`.
4. Тестовая публикация в закрытом режиме выполнена вручную, найдены `success_selectors`, `success_url_markers`, `post_url_regex` (раздел 4), записаны в конфиг.
5. Задайте лимиты и окно (раздел 5).
6. Только после этого включить `SOCIAL_PUBLISH_ENABLED=true` (в вашем окружении) и перезапустить Studio.
7. Первая публикация: закрытый пост, «да» на одну площадку, проверка ссылки и скриншота, удаление поста вручную.
8. Результат (что сработало, что нет, скриншоты) пришлите нам, чтобы мы отметили площадку как проверенную с датой и версией интерфейса. Без этого она остаётся «не проверена вживую».
