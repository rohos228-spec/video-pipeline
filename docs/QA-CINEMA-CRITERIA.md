# Кино-критерии — #61 (проверка `n_excel_gpt_1`)

Закадровый текст **не меняем**. Сценарий = 6 нод chrono_dyn
(скелет → персонажи / мир / стиль → действие → камера), затем локальная
сборка, затем эта проверка. Видео — только после `verdict: pass`.

## Как должно выглядеть кино

Вертикаль 9:16, документальная драма по закадру. Зритель всегда понимает:
**кто** в кадре, **где** он стоит, **что изменилось** с прошлого шота,
**зачем** этот ракурс. Лицо героя в ключевых битах — не спина массовки
и не пустой коридор.

Сцена строится так:

1. **Скелет** — 1 ячейка закадра = 1 сцена. Текст ячейки не режется.
2. **Персонажи / мир / стиль** — паспорта, не границы сцен.
3. **Действие** — фазы внутри сцены: каждая фаза меняет информацию
   (кто / что / где / состояние), не только крупность.
4. **Камера** — 1 фаза = 1 shot. SET только если фаза явно establishing.
5. К одной VO-ячейке может быть много визуальных кадров, если суммарный
   тайминг = `время_сек` этой ячейки.

## Четыре оси (все обязательны для pass)

| Ось | Pass | Fail |
|-----|------|------|
| **Стиль** | Одна световая дуга, палитра не прыгает без причины, locNN узнаваем | Смешение эпох/света; «нейтральный офис» вместо места из world |
| **Логика** | Хронология VO; персонаж cNN согласован со скелетом; место заполнено | Чужие люди в кадре; пустое `место`; закадр разрезан по шотам |
| **Интерес** | Фаза несёт новый удар (эмоция / пространство / социальный узел) | Повтор pan-текста в акцент/смысл/особенность; лестница VLS→MS→CU без события |
| **Качество** | Entity c01… есть; кто_в_кадре конкретный; лицо когда бит про человека | 0 Entity; клоны полей; спины толпы; `[object Object]` |

## 6 нод, которые чиним при fail

`skeleton` · `characters` · `world` · `style` · `action` · `camera`

Проверка не переписывает закадр и не является apply-ops сборщиком.
`related` в отчёте указывает, какую из 6 нод перезапускать.
