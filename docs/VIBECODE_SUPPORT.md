# Поддержка Vibecode в оркестраторе

Причина: ноды группы `script_frames_qc` принудительно идут на Vibecode (`llm_override.bind_project_llm`), а слой оркестратора был рассчитан на Kie Responses.

## Что сделано (проверено тестами на заглушках и офлайн-стендом, без платных вызовов)

- Единая проверка завершённости ответа для Responses и Chat Completions: `app/services/llm_completion.py`. Раньше признак «завершён» у Chat Completions всегда был `False`, из-за чего блокировались шаги восстановления и падала QC-нода.
- Журнал: `provider` и модель в `model_start` / `model_end` / `model_error`; `finish_reason` из потока; усечённый ответ (`length`) удерживает выполнение; неопределённые таймауты фиксируются как `uncertain`.
- Решатель: второй утверждённый маршрут `gpt-5.6-sol-vibecode` (`/v1/chat/completions`, один запрос без потока и без автоповторов, `DecisionTruncated` при усечении). Ключ только из настроек, `vk-` маскируется.
- Профиль: `vibecode-json-repair-v1`; провайдер профиля должен совпадать с провайдером упавшей попытки (проверка в четырёх точках); Kie-профиль на Vibecode-ноде невозможен.
- Стоимость: по каталогу Vibecode, помечена как неоткалиброванная; тариф Kie к Vibecode не применяется.
- Ошибки: код `gpt_credits` для HTTP 402 (Vibecode и Kie).
- `script_frames_qc`: исправлена QC-проверка, требовавшая статус Responses; правило из `PassStopError` попадает в `node_error` как поле `rule`; привязка разбора к запросу не зависит от параллельных пачек.
- Стенд: `scripts/e2e_vibecode_script_frames_qc.py` (только офлайн, с запретом любых нелокальных запросов): обычное восстановление, `--recovery retry_profile`, недобор кадров.

## Не проверено на реальном Vibecode

- Формат потока (`finish_reason`, заключительный чанк с `usage`), имя параметра лимита токенов (`max_completion_tokens` или `max_tokens`), работа через relay на ответах 60–90 с.
- Реальная цена: использована цена снимка каталога, возможна разница до ×3.
- Тело ответа 402 у Vibecode.
- Для этого нужна одна живая проба с потолком расходов.

## Живые прогоны восстановления на Vibecode (2026-10-05)

Стенд `scripts/e2e_vibecode_script_frames_qc.py --live` на группе `script_frames_qc`: битые ответы рабочих запросов подставляются локально, решатель и повтор восстановления идут на настоящий Vibecode (`/v1/chat/completions`, `gpt-5.6-sol`), потолки 6 запросов и 10 центов.

- С одобренным профилем (`--recovery retry_profile`): PASS, 26 проверок. Решатель выбрал `retry_profile` с профилем `vibecode-json-repair-v1`, повтор вернул разбираемый JSON, восстановление подтверждено проверщиком, все 5 нод `done`. Около 2,4 цента по каталогу.
- Только простой повтор (`retry_same`, без профилей): NOT PASSED по сценарию, решение настоящей модели `human_review` (нет оснований повторять тот же запрос без исправляющего профиля). Это безопасное поведение: для нод, которые должны чиниться сами, в конфигурации решателя нужен одобренный профиль. Около 2,6 цента по каталогу.
- Не покрыто: как часто настоящая модель возвращает битый JSON, многопачечные запуски, реальные ответы остальных нод.
