## Живой прогон реальной ноды excel_gpt (2026-10-01)

`scripts/e2e_live_excel_gpt_recovery.py --live`, потолок владельца 10 центов, лимит 6 реальных запросов.
Реальное: приложение целиком, исполнитель ноды `n_excel_gpt_fw_script` с её промптами, диагностика,
Decision, профиль `production-json-repair-v1`, верификатор, модель `gpt-5-6-sol` на Kie.
**Не реальное по построению:** первые 18 попыток воркера (3 цикла нативных повторов) получили локальный
бракованный ответ `{"ops": }` — реальную модель нельзя заставить вернуть битый JSON по требованию.
Эти ответы не покидали машину и ничего не стоили.

Результат: PASS. Решение Decision = 1 реальный запрос, модель выбрала `retry_profile` с
`production-json-repair-v1`; повтор ноды = 1 реальный запрос; событие `profile_effective_context`
записано; `recovery_verification.verified = true`, `data_applied` (updated=1), нода `done`,
запись восстановления `verified`. Реальные запросы: 5464 вх. / 225 исх. токенов и 530 / 252;
оценка по таблице тарифов проекта около $0.0095, обе строки учёта привязаны к проекту 2.
`semantic_quality_verified = false`: система проверяет структуру и применение данных, но не смысловое качество.
Сухой прогон (`--dry`, все запросы к провайдеру физически отклоняются) подтвердил механику с нулевой стоимостью.

## Готовность текстовых нод к самовосстановлению (2026-10-02, без живых запросов)

Решение по нодам задаётся данными способностей (`node_capabilities.NodeCapability`), а не строками типов:
`profile_compatible`, `native_json_retry`, `volatile_attachment_names`, `recovery_continuation`.

- `plan`, `script` — включены: `retry_same`/`retry_profile`/`finish`. Проверено сухим прогоном
  `scripts/e2e_text_nodes_recovery.py --probe-retry {same,profile} --simulate-recovery`: реальный исполнитель упал нативно
  (9 попыток), инцидент `invalid_json`, реальные предусловия `recover_node` приняты, повтор выполнен реальным
  исполнителем (ответ — локальная фикстура, наружу ничего не уходит), запись восстановления `verified`,
  обязательный HITL остался `pending`. Нужен живой прогон Decision (`--live`) для окончательного заключения.
- `split` — НЕ включена: при битом JSON исполнитель штатно завершается через локальную разбивку закадра (нечего
  восстанавливать), а `parse_result` имеет `payload_required=false`, поэтому инцидент `invalid_json` невозможен.
- `image_prompts` — НЕ включена: нативный верификатор после первого неуспеха ставит hold на выполнение
  (`native_image_prompt_verifier`), старт воркера блокируется (`execution_held`), нативные повторы не исчерпываются,
  восстановление недостижимо по конструкции; инцидент также `contract_rejected`, а не `invalid_json`.
