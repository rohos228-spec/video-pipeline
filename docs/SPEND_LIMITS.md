# Локальные денежные лимиты надзорного слоя

Модуль `app/services/spend_guard.py`. Работает без сети: облачный рубильник `api_tracker_hook` не используется.

## Журнал
Таблица `spend_ledger` (основная БД, только добавление; UPDATE и DELETE запрещены триггерами). Поля: день (UTC), вид
(`reserve` резерв, `settle` разница факта и резерва, `actual` нативный вызов, `event`), провайдер, проект, запуск
(execution id или `plan:<id>`), источник, USD, кредиты. Создаётся при первом обращении (`ensure_schema`).

## Потолки (0 = без ограничения)
| Настройка | По умолчанию | Область |
|---|---|---|
| `SPEND_DAILY_CAP_USD` | 25 | все проекты, сутки UTC |
| `SPEND_PROJECT_CAP_USD` | 10 | проект, за всё время |
| `SPEND_RUN_CAP_USD` | 5 | один запуск или план |
| `SPEND_AUTO_KILL_ON_402` | true | авто-стоп при нехватке кредитов |

Резерв и проверка трёх потолков выполняются одним атомарным INSERT ... SELECT: две одновременные заявки не
пройдут вместе, если помещается только одна. Отказ: `SpendCapExceeded` с кодом `spend_cap_run`, `spend_cap_project` или
`spend_cap_daily`, суммой потрачено и потолком. Чтение никогда не блокируется (`check_allowed(..., read_only=True)`).

## Где подключено
- `ActionSupervisor.charge_request`: в той же транзакции, что счётчик запросов, до отправки. Оценка текстового запроса
  0.05 USD (измеренные вызовы 0.00005-0.008), платная отправка медиа 0.30 USD, статус, загрузка и upload бесплатны.
- Слой действий, `budget.reserve`: после проверки кредитного потолка плана; кредиты переводятся в USD по
  `kie_catalog.CREDIT_USD` (0.005). `budget.settle` дописывает разницу.
- Планировщик: резерв 0.05 USD перед POST; отказ превращается в `PlannerRefused` с тем же кодом.
- Факт: `observation._track_api_cost` (успешные вызовы с реальным ключом) закрывает резерв либо пишет нативный вызов.
  Нативные вызовы только учитываются в суммах и никогда не отклоняются.

## Авто-стоп по 402
Ошибка с кодом `gpt_credits` или `media_credits` (HTTP 402) при `SPEND_AUTO_KILL_ON_402=true` включает существующий
аварийный стоп (`kill_switch`, основание `credits_exhausted`, источник `spend_guard`, запись в историю и ActionRecord
каждого управляемого запуска). Стоп касается только надзорной работы: запросы супервизора, решения, восстановление, слой
действий, новый тик управляемого проекта. Неуправляемые нативные проекты не останавливаются. Снимается оператором.

## Интерфейс
`GET /api/projects/{id}/observations/spend`: суммы за сегодня, по проекту и запуску против потолков. Панель
оркестратора показывает их в блоке после аварийного стопа.

## Ограничения
- Суммы по нативным вызовам считаются по тарифной таблице трекера (калибровка только для текста), медиа нативного
  конвейера пишется оценкой (см. раздел ниже).
- Оценки консервативны; неизвестный факт оставляет резерв.
- Ошибка 402 на нативных медиа-путях Kie, Outsee, ElevenLabs включает авто-стоп через `media_spend`; браузерный Outsee не охвачен.

## Нативные платные медиа-вызовы (модуль `app/services/media_spend.py`)
Запись только учётная: вызов провайдера, его повторы и результат не меняются, ошибка записи не доходит до вызывающего
кода, запись идёт фоновой задачей (локальная вставка, без ожидания в запросе). Строки `spend_ledger` с источником
`media_native`, проект берётся из `_cost_project`. Запись выключена без реального ключа провайдера (пустой или
`synthetic*`) и внутри pytest (флаг `media_spend.TEST_FORCE` только для тестов).

| Провайдер | Точка подключения | Оценка |
|---|---|---|
| Kie (jobs/veo/suno/runway) | `kie_http.create_task` (стоимость и task id), `poll_task` (статус, число опросов одной строкой с 0 USD) | `kie_catalog.estimate_credits` x `CREDIT_USD`; модель без цены: строка запроса с `cost_unknown=true` |
| Kling-запасной клиент | `generate_kie_video`, ветка без каталожной модели (одна строка на вызов) | каталог `kling-2-6-i2v` / `-t2v`, иначе `cost_unknown=true` |
| Outsee API | обёртка вокруг `outsee_http.generate_image/generate_video` в `outsee_retry` | тарифа в коде нет: всегда `cost_unknown=true` |
| ElevenLabs TTS | каждый POST в `elevenlabs_api` (повторы и повтор без прокси считаются отдельно) | символы x `ELEVENLABS_USD_PER_CHAR` (0.0003, **не откалибровано**); при заголовке `character-cost` пишется строка `settle` |
| ElevenLabs sound effects | `sfx_gen._elevenlabs_sfx` | секунды x `ELEVENLABS_SFX_USD_PER_SEC` (0.012, **не откалибровано**) |

Неопределённый исход (таймаут, обрыв, ответ без task id) пишется по оценке: запрос мог быть принят. Однозначный отказ
(4xx, в том числе 402) пишется с 0 USD.

HTTP 402 или исчерпание кредитов на этих путях вызывает `spend_guard.engage_on_credit_error` (при
`SPEND_AUTO_KILL_ON_402=true`, только надзорный стоп) и пишет строку `event` с источником `media_402`. Нативная работа
не останавливается.

`provider_task_ledger` (основная БД, только добавление, UPDATE и DELETE запрещены триггерами): проект, ключ кадра или
клипа (имя файла без суффикса), task id, провайдер, модель, событие, статус, оценка. Состояние задачи это её последняя
строка (`submitted`, затем `pending` или `succeeded` или `failed`). Повторные отправки и опросы не меняются, таблица
нужна как durable-основа для будущего «возобновить опрос». `GET /api/projects/{id}/observations/provider-tasks`.

Диагностика: таймаут или обрыв после отправки в клиентах ElevenLabs и Kie поднимается как `ElevenLabsUncertainError` /
`KieUncertainError` (подклассы прежних ошибок) и даёт `uncertain_request`.

Ограничения: тариф Outsee и Kling-запасного клиента (task id) не учтены, task id запасного Kling-клиента не
пишется; `character-cost` не проверялся на реальном ответе; константы ElevenLabs оценочные.
