# Доска монтажа — анализ и топ-30 улучшений

Разбор кнопки **«Монтаж»** и её панели после переноса редактора сцены в строки
доски (Studio v532). Ниже: как всё устроено сейчас, где именно узкие места и
30 улучшений по приоритетам — с файлами, которые придётся тронуть.

SoT кода:

| Что | Файл |
|-----|------|
| Кнопка «Монтаж» над нодой «Сборка» | `web/src/components/canvas/assemble-montage-board.tsx` (`AssembleMontageTrigger`) |
| Панель монтажа (таблица кадров) | тот же файл (`AssembleMontageBoard`) |
| Клетки строк сцены | `web/src/components/canvas/montage-scene-cells.tsx` |
| Данные доски | `app/services/montage_board.py` → `GET /api/projects/{id}/montage-board` |
| Поля сцены / якоря кадра | `app/services/montage_scene_editor.py` |
| Запись правок | `app/services/montage_coverage_ops.py` (`coverage_*`) |
| Очередь правок | `app/services/montage_board_meta.py` (`normalize_queue_ops`), `POST …/montage-board/queue` |
| Применение | `app/services/montage_board_apply.py`, `montage_board_regen.py` |
| Вставка / удаление кадров | `app/services/montage_board_frames.py` |

## Как работает сейчас

1. Кнопка «Монтаж» на канвасе (`-top-9` над нодой `assemble`) открывает
   полноэкранную панель — это единственное «окно», и оно остаётся.
2. Внутри панели — таблица: колонка = кадр, ряд «Сцены» группирует кадры одной
   VO-ячейки, строки = закадр, сцена, характеристики кадра, референсы,
   изображения, видео, таймкоды.
3. Правка кадра больше **не** открывает панель: роль в покрытии, крупность,
   ракурс, движение, стык, действие и якорь правятся в клетке кадра; формат
   сцены, свет и набор — в клетке на всю ячейку.
4. Любая правка кладётся в очередь (`pending_ops`) и применяется кнопкой
   «Применить правки»: сначала `coverage_*` в БД, затем перегенерация картинок.

## Что мешает прямо сейчас (корни проблем)

- **Смысл сцены только читается.** `scene_sense`, `тип_сцены`, `предметы`,
  `фон`, `акцент`, `особенность`, `место`, `персонажи` доска показывает, но
  `COVERAGE_OP_TYPES` таких операций не знает — поменять смысл сцены из UI
  нельзя, только через Excel/ноды.
- **Персонажами нельзя управлять с доски.** Строка «Референсы» — read-only
  превью (`RefsCell`): нет ни отвязки, ни выбора из уже сгенерированных
  `data/<project>/characters/`, ни загрузки нового лица, хотя эндпоинты
  (`GET …/assets?kind=…`, `POST …/assets/hero/replace`) уже есть.
- **`+` внутри сцены делает не то.** `insert_montage_frame` всегда создаёт
  VO-родителя (`role="vo_parent"`), поэтому «добавить шот в сцену» превращается
  в новую ячейку закадра вместо дочернего кадра по лестнице шаблона.
- ~~**Якорей может быть больше, чем кадров.**~~ Сделано: дописанный якорь сам
  создаёт шот сразу за правленым кадром (`_grow_cell_shots`), номера кадров и
  очередь после вставки правит `remap_frame_numbers`. Отдельной кнопки
  «разбить кадр по якорям» нет и не нужно.
- ~~**Доска дёргалась на первой правке.**~~ Сделано: строка счётчиков в шапке
  держит высоту всегда, метка «в очереди» стала точкой поверх клетки, а
  `content-visibility` клеток помнит последний размер (`auto 240px auto 180px`).
  До этого layout уезжал на ±20px между нажатием и отпусканием мыши, и первый
  клик по кнопке в клетке терялся.
- **Правка сцены обновляет картинку только у первого кадра ячейки.** Свет и
  набор пишутся всем кадрам группы (`apply_coverage_light` / `_set`), а
  `image_ai_change` в очередь встаёт на один кадр (`queueSceneOps`).
- **Из очереди нельзя вынуть одну операцию.** Есть только «Применить правки»
  целиком; ошибочный клик по чипу снимается лишь повторным кликом по прежнему
  значению, а `coverage_delete` не снимается вообще.

## Топ-30 улучшений

### P1 — правки, которых не хватает каждый день

1. **Правка смысла сцены.** Ops `coverage_sense` / `coverage_visual_type` →
   `attrs.смысл_сцены` / `тип_сцены` всем кадрам ячейки (по образцу
   `apply_coverage_light`), поля — в строку «Сцена (ячейка)».
   `montage_coverage_ops.py`, `montage-scene-cells.tsx`.
2. **Правка места и персонажей сцены.** Ops `coverage_place` /
   `coverage_characters`: место идёт в `camera_subdivide.место` и `кадры[].место`,
   персонажи — в `attrs.персонажи_сцены`. Сейчас это самый частый повод
   открывать Excel.
3. **Правка предметов / фона / акцента.** Ops для `предметы`, `фон`, `акцент`,
   `особенность_сцены` — те же поля, что читает `_scene_common`, тем же
   инлайновым инпутом.
4. **Отвязать персонажа от кадра.** Крестик на превью в «Референсах» →
   `attrs.персонажи`/`persons` минус id, без похода в Excel.
5. **Добавить персонажа из уже сгенерированных.** Пикер по
   `GET /api/projects/{id}/assets?kind=characters` (папка
   `data/<project>/characters/`) прямо в клетке референсов.
6. **Загрузить новое лицо персонажа с диска.** Переиспользовать
   `POST …/assets/hero/replace` (он уже умеет `replace_path`) — кнопка «загрузить»
   на превью и на пустой клетке.
7. **Создать нового персонажа с доски.** id + имя + файл → запись в лист
   `персонажи` (`app/services/excel_characters.py`) и в `entities`, затем
   привязка к кадру. Сейчас новый персонаж возможен только через ноды.
8. **`+` внутри сцены = дочерний шот.** `insert_montage_frame(kind="child")`:
   `role="shot"`, `parent_uuid` родителя, план/ракурс из лестницы шаблона
   (`catalog_shot_rows`) и `_refresh_shots_in_beat`.
9. ~~Разбивка кадра по якорям~~ — **сделано без отдельной кнопки**: `+ якорь`
   в клетке кадра, `apply_coverage_anchors` → `_grow_cell_shots` создаёт шот и
   раздаёт куски VO. Осталось только дотянуть: новому шоту нужна картинка
   (сейчас клетка пустая до ручной перегенерации).
10. **Склейка двух VO-ячеек / разрезание одной.** Split по позиции курсора в
    закадре и merge соседних ячеек (`split_vo_by_anchors` уже считает нарезку) —
    сейчас пересборка сцен делается только полным прогоном нод.

### P2 — управляемость очереди и предсказуемость применения

11. **Снять одну операцию из очереди.** Панель списка `pending_ops` с крестиком
    у каждой (тип, кадр, значение) — сейчас очередь видна только счётчиком.
12. **Отмена `coverage_delete`.** Кадр «на удаление» должен уметь вернуться;
    сейчас метка ставится и снимается только через сброс всей очереди.
13. **Перегенерация всех кадров ячейки при правке сцены.** В `queueSceneOps`
    для `coverage_light` / `coverage_set` / `coverage_template` ставить
    `image_ai_change` каждому кадру группы, а не только первому.
14. **Выбор «перегенерировать / не трогать картинку».** Тумблер в шапке панели:
    сейчас regen привязан жёстко к типу правки (`visualTypes`).
15. **Предпросмотр правки до применения.** Diff «было → станет» по каждой
    операции: `preview_template_ladder` уже даёт такой расчёт для шаблона,
    остальным ops нужен аналог.
16. **Батч-правка выделенных кадров.** Shift-выделение колонок и одна правка
    на все (крупность/ракурс/движение) — сейчас каждый кадр кликается отдельно.
17. **Копировать характеристики соседнего кадра.** Кнопка «как в #N» —
    частый кейс при чередовании шотов внутри T5/T8.
18. **Отмена последнего применения.** Снимок затронутых `attrs` перед
    `apply_coverage_op` и кнопка «откатить последнее применение».
19. **Явная ошибка вместо пустого значения.** `apply_coverage_*` бросает
    «ракурс пустой» — очередь должна отбрасывать такие ops на входе
    (`normalize_queue_ops`) и подсвечивать клетку.
20. **Прогресс применения по строкам.** Сейчас `applyProgress` — общий
    счётчик; полезнее подсветка конкретной клетки, которая в работе.

### P3 — навигация, читаемость, надёжность

21. **Запоминать свёрнутые строки.** `collapsedRows` в `localStorage` по
    проекту: 17 строк каждый раз разворачиваются заново.
22. **Пресеты набора строк.** «Только медиа» / «Только сцена» / «Всё» —
    один клик вместо десяти сворачиваний.
23. **Заморозить первую колонку и шапку по вертикали.** Заголовок строк уже
    `sticky left-0`; при длинной таблице не хватает `sticky top-0` для рядов
    «Строка» / «Сцены».
24. **Переход к кадру по номеру.** Поле «#» в шапке + прокрутка к колонке:
    сейчас на 60+ кадрах ищут глазами.
25. **Клавиатура в строках сцены.** Tab / стрелки между клетками одной строки,
    цифры 1–5 на крупность — правка чипами мышью медленная.
26. **Показывать конфликт с лестницей шаблона.** Если крупность кадра не равна
    плану его позиции в шаблоне (`template_ladder_for_ui`), помечать клетку —
    сейчас расхождение видно только развернув лестницу.
27. **Подсветка непокрытого закадра.** `covers_text` из
    `_frame_anchor_payload` уже считается, но в UI не выводится: кусок ячейки
    без якоря и кадра остаётся незамеченным.
28. **Порядок кадров перетаскиванием.** Дробный `sort_key` +
    `renumber_frames_by_sort_key` уже позволяют переставлять кадры; в UI есть
    только перенос картинок между слотами.
29. **Дублировать кадр целиком.** `insert_frame_after` + копия `attrs` и
    промтов — быстрый способ сделать вариант шота.
30. **E2E-тест доски.** Playwright-сценарий поверх `scripts/dev_seed_montage_scene.py`
    и `scripts/dev_check_montage_rows.py`: правка каждой строки → очередь →
    применение → значения в БД. Сейчас на UI доски автотестов нет.

## Порядок, в котором это выгодно делать

1. Пункты 1–3 и 11 — снимают возвраты в Excel и страх «нажал не туда».
2. Пункты 4–7 — персонажи с доски (самая частая просьба оператора).
3. Пункты 8–10 — структура сцены: шоты и границы ячеек без прогона нод.
4. Пункты 13–15 и 19 — предсказуемость применения и меньше пустых правок.
5. Остальное — по мере роста числа кадров в проекте.
