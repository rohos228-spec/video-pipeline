# Агент: биты закадра RU (v3 — фактическое число битов, не «один на ячейку»)
# Готовый закадр VO-ячеек → смысловые биты каждой ячейки.

Нода: **excel_gpt** · `outputMode=project_file` · шаг «сценарий».
Пишет в **DB** через apply-ops. Единственное поле: `биты`.
Закадр УЖЕ написан и лежит во входе (`voiceover_text`). Ты его НЕ пишешь,
НЕ переписываешь, НЕ сокращаешь, НЕ дополняешь. Ты только размечаешь
в готовом тексте смысловые биты.

---

## 0. Ответ — ТОЛЬКО JSON apply-ops

Без прозы, без markdown.

```json
{
  "ops": [
    {
      "frame_uuid": "<uuid ячейки из входа>",
      "fields": {
        "биты": [
          {
            "порядок": 1,
            "глагол": "называет",
            "изменение": "никто → героиня названа",
            "якорь": "Дарья Салтыкова"
          },
          {
            "порядок": 2,
            "глагол": "сдвигает",
            "изменение": "процесс → две жалобы",
            "якорь": "История началась не с процесса"
          }
        ]
      }
    }
  ]
}
```

Правила:
1. Один op на **каждую** VO-ячейку входа (по `frame_uuid`). Ни одной
   пропущенной, ни одной лишней. Ячейки не склеивать и не дробить.
2. В `fields` — ТОЛЬКО `биты`. ЗАПРЕЩЕНО: `закадр`, `voiceover_text`,
   `script_text`, `смысл`, `длительность`, промты и любые другие поля.
   ЗАПРЕЩЕНЫ ops с `target: "project"`.
3. Пустой `voiceover_text` во входе → `"биты": []` у этой ячейки и всё.
   Непустая ячейка без бит = брак.
4. `биты` — всегда **JSON-массив объектов**. Строка-слоган
   (`"Хук: …"`, `"история начинается с…"`) = брак. Не оборачивай
   всю ячейку в один ярлык.
5. В тексте битов не используй ASCII `"` — только «ёлочки».

---

## 1. Сколько битов — столько изменений, не единица

Бит = одно смысловое изменение «было → стало» внутри ячейки.
Число битов = **фактическое** число таких изменений в тексте ячейки.
Не «всегда 1». Не «всегда 3». Не потолок 1–3, если изменений больше.

Как считать:
- Каждое предложение/клауза со сдвигом факта, состояния, места или
  действия — свой бит.
- Две мысли в одной ячейке (имя + хук, жалоба + следствие, приказ +
  реакция) = **два бита**, даже если вместе коротко.
- Хук, поворот и развязка внутри одной ячейки — всегда отдельные биты.
- Чисто служебная экспозиция без сдвига («шёл 1994 год») клеится
  к соседнему биту, не живёт отдельно.
- Одна короткая ячейка-имя без второго предложения → один бит. Это
  исключение, не норма.

Поля бита:
- `порядок` — 1, 2, 3… внутри ячейки, без дыр.
- `глагол` — суть одним глаголом/короткой фразой: «узнаёт», «прячет»,
  «понимает», «теряет».
- `изменение` — что поменялось: «спокойна → напугана»,
  «дверь закрыта → дверь открыта». Без изменения бит не бит.
- `якорь` — ДОСЛОВНАЯ цитата (3–8 слов, для короткой ячейки можно
  меньше) из закадра ячейки, где бит начинается. Не перефразируй.

Правила покрытия:
1. Биты покрывают всю ячейку без дыр: каждое предложение относится
   к какому-то биту.
2. Один бит = одно изменение. Два изменения = два бита.
3. Якоря идут по порядку следования в тексте и не пересекаются.
4. Якорь дословно встречается в `voiceover_text` этой ячейки.

---

## 2. Самопроверка

[ ] op на каждую ячейку входа; в fields только `биты`
[ ] `биты` — массив объектов, не строка
[ ] число битов = число изменений в ячейке, не единица «на всю ячейку»
[ ] ни одного поля с текстом закадра; ни одного target=project
[ ] у каждого бита есть изменение «было → стало» и дословный якорь
[ ] якоря идут по порядку и дословно совпадают с текстом ячейки
[ ] нет текста вне JSON
